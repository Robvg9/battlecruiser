# B2.3 — Centro de Control Operacional

## Qué se implementó

Capa de **lectura/acción** sobre la infraestructura Offline-First ya existente.
NO crea una segunda cola, ni un store IndexedDB nuevo, ni una caché nueva, ni
un sistema de sincronización paralelo, ni permisos paralelos, ni RPC duplicados.

El Centro de Control vive en la pestaña **"Centro de Control"** (antes "Resumen",
la pantalla inicial post-login) y responde:

- ¿Estoy conectado?
- ¿Hay operaciones pendientes?
- ¿Hay errores?
- ¿Qué necesita mi atención?
- ¿Qué está pasando?
- ¿Qué ocurrió recientemente?
- ¿Qué debo hacer ahora?

### Secciones

1. **Estado del negocio** (B2.3-A): tarjeta con color derivado del estado real
   (crítico=burdeos, atención=oro, normal=salvia). Nunca "Operativo" si hay
   `REQUIERE_ATENCION` o pendientes. Conectividad y sincronización son estados
   distintos.

2. **Requiere atención** (B2.3-B/C/D): lista priorizada de operaciones en
   `REQUIERE_ATENCION`, cada una con tipo, resumen, motivo/error, fecha e
   intentos. Acciones: Ver detalle / Reintentar / Eliminar (reutilizan
   `reintentarOperacionPendiente`, `eliminarOperacionPendienteConfirmada`,
   `mostrarDetalleOperacion`).

3. **Operaciones pendientes** (B2.3-J): resumen compacto + camino directo al
   panel de Pendientes existente (no se reconstruye).

4. **Inventario** (B2.3-K): stock bajo con proyección local reutilizando
   `ajustePendiente` (la autoridad existente). El Centro solo presenta; no
   recalcula stock.

5. **Actividad reciente** (B2.3-L): ventas + transferencias + vales de `_cache`,
   sin consultas nuevas.

## Limitaciones honestas (backend que NO existe todavía)

Estos bloques de la especificación B2.3 **no se implementaron** porque el
backend/estructura real para respaldarlos no existe en el proyecto. No se
inventaron datos ni permisos paralelos.

### B2.3-E/F — Vista Admin vs Trabajador
**No existe sistema de roles real.** El proyecto NO expone `user_metadata.role`
ni un RPC de roles. El único permiso real es `tiene_permiso` para la sección
`presentaciones`. Por eso la vista del Centro de Control es la misma para todo
usuario autenticado y NO se inventa una distinción admin/trabajador que el
backend no respalda. **Falta:** un RPC/tabla de roles (`usuarios.role` o
equivalente) para filtrar información por permiso real.

### B2.3-N — Responsabilidades / turnos
**No existe backend de responsabilidades ni turnos.** No hay tablas de turnos,
sesiones de turno, responsabilidades tachables ni entrega/recepción de turno.
**Falta:** backend completo de turnos + responsabilidades (roadmap posterior
a B2.3 según el Cerebro).

### B2.3-O — Solicitudes administrativas
**No existe backend de solicitudes** (gastos, bajas, reinversiones con
aprobación). **Falta:** tablas y RPC de solicitudes + flujo de aprobación.

### Personal (usuarios activos, expedientes)
**No existe backend de usuarios activos ni expedientes.** **Falta:** módulo de
personal/expedientes.
